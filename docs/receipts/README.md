# Receipt format: `elivo-receipt-1`

> **Testnet prototype. Payout firms and SPEI receipts are simulated. Contract unaudited.**

Each funded batch ends with a signed receipt. The receipt records every payout: its amount, which firms held it, when it was delivered or why it was refunded, any penalty the late firm paid, and the transaction hashes. Its hash is anchored in the escrow contract, so anyone can check the receipt against the chain without trusting the operator.

This folder publishes the format so that tools in any language can check receipts:

| File | What it is |
|---|---|
| [`elivo-receipt-1.schema.json`](elivo-receipt-1.schema.json) | JSON Schema (draft 2020-12) for the receipt file |
| [`vectors/`](vectors/) | Test vectors and a `manifest.json` with the expected verdict and hash for each |

A real anchored receipt from the testnet reference run (batch 5) is at [`apps/web/public/receipts/testnet-batch-5.json`](../../apps/web/public/receipts/testnet-batch-5.json).

## Fields

- **Amounts:** USDC base units (6 decimals) as decimal strings: `"1000000000"` is 1,000 USDC. `amount_mxn` has 2 decimals.
- **Times:** `*_ns` fields are NEAR block times in nanoseconds since the Unix epoch, as strings.
- **Payees:** never named. `payee_ref` is `sha256(salt ‖ CLABE)` in hex, and `clabe_last4` is the last 4 digits. The salt stays with the operator.
- **State:** `Delivered`, or `Refunded` (`excluded: true` with a `reason` such as `ACCOUNT_CLOSED` means the account was closed and no penalty applies).
- **Penalties:** `penalties_total` is what the late firm's bond paid to the funder (the DAO) for that payout.
- **Totals**, recomputable from the rows:
  - `locked` = Σ (amount + 25 bps fee buffer);
  - `paid_to_firms` = Σ over delivered payouts of (amount + amount × `quote_bps` / 10,000);
  - `penalties` = Σ `penalties_total`;
  - `returned_to_funder` = `locked` − `paid_to_firms` + `penalties`.

## Signing and the anchored hash

1. **Body:** the receipt without its `signature` field.
2. **Canonical bytes:** the body serialised with the [RFC 8785](https://www.rfc-editor.org/rfc/rfc8785) JSON Canonicalization Scheme, as UTF-8.
3. **Signature:** ed25519 over those bytes, stored as `signature.sig` (base64), with `signature.public_key` as `ed25519:<base58>`.
4. **Anchored hash:** `base58(sha256(RFC 8785 bytes of the whole receipt, signature included))`. The router writes it to the escrow with `anchor_receipt`. `get_batch` returns it as `receipt_hash`, together with the batch's `receipt_pk`.

## How to verify a receipt

Never trust the key or escrow written in the file. Take them from the chain:

1. Choose the escrow account yourself. Call its view method `get_batch({"batch_id": <batch_id>})`.
2. Check that `signature.public_key` equals the batch's `receipt_pk`, and that the ed25519 signature verifies over the canonical body.
3. Check that the anchored hash computed from the file equals the batch's `receipt_hash`.
4. Recompute the totals from the rows.

Three ways to do this here:
- **In the browser:** the web app's `/verify` page runs all four checks and then offers a CSV export.
- **Command line:** `pnpm verify-receipt <file> --chain --rpc <url> --escrow <account>`.
- **Code:** `packages/shared/src/receipt-web.ts` (browser-safe, WebCrypto) and `packages/shared/src/receipt.ts` (Node).

## Test vectors

`vectors/manifest.json` lists each case:
- the file;
- the public key to verify it with;
- the expected verdict: `ok`, `bad_signature`, `key_mismatch` or `malformed`;
- the anchored hash, where there is one.

A verifier is compatible when it returns the same verdict and hash for every entry.

The vectors use fictitious accounts and a fixed test key, and are generated by `pnpm gen:vectors`. The test suite checks that the committed files match the generator byte for byte, and that both verifiers agree with the manifest.

## CSV export

The CSV export (from `/verify`) has one row per payout:
- USDC values with 6 decimals, ISO 8601 UTC times;
- the batch id and receipt hash on every row, so a row stays traceable after import;
- RFC 4180 quoting with CRLF line endings, and a leading `'` on any cell that starts with `=`, `+`, `-` or `@`.
